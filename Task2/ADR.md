### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

| **№** | **Требование**                                                                                          |
|:-----:|:--------------------------------------------------------------------------------------------------------|
|   1   | SLA: доступность сервиса истории ≥ 99.9%                                                                |
|   1   | Данные об истории заказов не должны быть потеряны даже при сбое одного из сервисов                      |
|   1   | Запрос истории заказов пользователем должен обрабатываться за ≤ 1–2 секунды при среднем размере истории |
|   2   | При очень длинной истории (>1000 заказов) должна работать пагинация                                     |
|   3   | Сервис должен быть оптимизирован под частые операции чтения                                             |
|   3   | История должна отражать все изменения заказа (создание, подтверждение, отмена, доставка)                |
|   3   | Доступ к истории заказов должен быть только у владельца учётной записи                                  |
|   3   | Нужно определить срок хранения истории                                                                  |

### <a name="_qmphm5d6rvi3"></a>**Решение**

Решено реализовать отдельный сервис для работы с историей - Order History Service.
Данный сервис читает события по изменению статуса заказа и сохраняет историю.
При недоступности сервиса заказов историю все равно можно будет просматривать.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

1) Хранить историю в Order Service
   Недостатки:
    * Order Service теперь не только отвечает за бизнес-логику оформления заказов, но и за аналитику истории.
    * Уменьшается гибкость, так как история хранится в той же реляционной бд. При реализации отдельного Order History Service можно
      подобрать другую бд.

2) Order History Service + Kafka (все то же самое как в выбранном решении, но с элементами event sourcing)
   Недостатки:
    * Повышение порога входа, так как не все разработчики знакомы с Kafka, Event Sourcing
    * Повышенная сложность разработки, поддержки
